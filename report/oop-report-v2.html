1.1 ที่มาและความสำคัญ

ในการเรียนวิชาวิธีเชิงตัวเลข (Numerical Methods) ผู้เรียนต้องคำนวณคำตอบของปัญหาทางคณิตศาสตร์หลายประเภท เช่น การหารากของสมการ การแก้ระบบสมการเชิงเส้น การแทรกและการคาดคะเนค่า ตลอดจนการหาพื้นที่ใต้เส้นโค้งและอนุพันธ์เชิงตัวเลข ซึ่งแต่ละวิธีต้องทำการคำนวณซ้ำ ๆ จำนวนมาก ถ้าทำด้วยมือจะเสียเวลามากและเกิดข้อผิดพลาดได้ง่าย นอกจากนี้ผู้เรียนยังควรเข้าใจ "ขั้นตอนการคำนวณ" ของแต่ละวิธี ไม่ใช่แค่คำตอบสุดท้ายเท่านั้น

ผู้จัดทำจึงพัฒนาโครงงาน FastNumeric เป็นเว็บแอปพลิเคชันสำหรับคำนวณวิธีเชิงตัวเลข จำนวน 6 หมวด 11 วิธี โดยโปรแกรมไม่เพียงแสดงคำตอบสุดท้าย แต่แสดง "ขั้นตอนการคำนวณ" และ "ตารางการทำซ้ำ (Iteration Table)" ครบทุกขั้นตอน ผู้ใช้สามารถตรวจสอบการคำนวณย้อนกลับได้ทีละรอบ เหมาะกับการใช้ตรวจคำตอบและทบทวนวิธีทำของผู้เรียน

ด้านการพัฒนา โปรแกรมถูกออกแบบด้วยหลักการเขียนโปรแกรมเชิงวัตถุ (Object-Oriented Programming: OOP) อย่างเต็มรูปแบบ ทั้งการซ่อนรายละเอียด (Encapsulation) การสืบทอดคุณสมบัติ (Inheritance) ความเป็นนามธรรม (Abstraction) รูปแบบพฤติกรรมหลากหลาย (Polymorphism) และการประกอบวัตถุ (Composition) เพื่อให้ระบบแยกชั้นความรับผิดชอบชัดเจน เพิ่มวิธีคำนวณใหม่ได้โดยไม่ต้องแก้โค้ดเดิม

1.2 ประเภทของโครงการ

โครงการนี้เป็นโครงการประเภทพัฒนาซอฟต์แวร์ประยุกต์ (Application Development) เป็นเว็บแอปพลิเคชันที่ทำงานบนเว็บเบราว์เซอร์ ประกอบด้วยส่วนติดต่อผู้ใช้ (Frontend), ส่วนประมวลผลและเก็บข้อมูล (Backend + Database) และสามารถติดตั้งทำงานบนเซิร์ฟเวอร์ได้ด้วยเทคโนโลยีคอนเทนเนอร์ (Docker)

1.3 ประโยชน์ของโครงการ

  1. คำนวณวิธีเชิงตัวเลขได้ถูกต้อง รวดเร็ว ครอบคลุม 6 หมวด 11 วิธีที่ใช้เรียนในรายวิชาวิธีเชิงตัวเลข
  2. แสดงขั้นตอนการคำนวณและตารางการทำซ้ำทุกวิธี ช่วยให้ผู้เรียนเข้าใจกลไกของอัลกอริทึม ไม่ใช่แค่คำตอบ
  3. ตรวจคำตอบการบ้านหรือการคำนวณด้วยมือได้รวดเร็ว ลดข้อผิดพลาดจากการคำนวณซ้ำ ๆ
  4. บันทึกประวัติการคำนวณลงฐานข้อมูล นับจำนวนครั้งที่คำนวณโจทย์เดิม และสรุปสถิติให้เห็นภาพรวม
  5. เป็นตัวอย่างการนำหลัก OOP ไปใช้กับโจทย์จริงด้านคณิตศาสตร์ เช่นการแยกชั้นอัลกอริทึมออกจากการแสดงผล

2.4 แนวคิดการเขียนโปรแกรมเชิงวัตถุ (OOP)

2.4.1 Constructor

คลาสวิธีคำนวณทุกคลาสกำหนดข้อมูลเฉพาะของตัวเองไว้ใน constructor แล้วส่งต่อให้คลาสแม่ผ่าน super() ตัวอย่างคลาส BisectionMethod กำหนดว่าอินพุตของวิธีมีอะไรบ้าง (สมการ, ช่วง XL–XU, Tolerance, Max Iterations):

class BisectionMethod extends BaseMethod { constructor() { super({ key: 'bisection', category: 'root', name: 'Bisection Method', nameTh: 'วิธีแบ่งครึ่งช่วง', fields: [ { name: 'fx', label: 'f(x) = 0', type: 'expression' }, { name: 'xl', label: 'XL (ปลายซ้าย)', type: 'number' }, { name: 'xu', label: 'XU (ปลายขวา)', type: 'number' }, { name: 'tol', label: 'Tolerance', type: 'number', default: 1e-6 }, { name: 'maxIter', label: 'Max Iterations', type: 'int', default: 100 }, ], }); } }

ข้อมูล fields นี้ถูกส่งต่อไปถึง Frontend ผ่าน API GET /api/methods เพื่อสร้างฟอร์มกรอกข้อมูลของแต่ละวิธีโดยอัตโนมัติ — เพิ่มวิธีใหม่ก็ได้ฟอร์มใหม่ทันทีโดยไม่ต้องแก้ Frontend

2.4.2 Encapsulation (การซ่อนรายละเอียด)

registry.js ซ่อนโครงสร้างเก็บวัตถุ (Map) ไว้ภายใน ภายนอกเรียกผ่านฟังก์ชัน register / getMethod / listMethods เท่านั้น และป้องกัน key ซ้ำตั้งแต่ตอนลงทะเบียน:

// registry.js — ซ่อน Map ไว้ข้างใน ภายนอกเข้าถึงผ่านฟังก์ชันเท่านั้น const methods = new Map(); function register(method) { if (methods.has(method.meta.key)) { throw new Error(`method key ซ้ำ: ${method.meta.key}`); } methods.set(method.meta.key, method); } function getMethod(key) { return methods.get(key) || null; }

นอกจากนี้ชั้น validation ยังทำหน้าที่เป็น "ด่านเดียว" ในการตรวจอินพุตทุกชนิด (จุดทศนิยะ, จำนวนเต็ม, ตารางจุด, เมทริกซ์, สมการ) โค้ดคำนวณจึงไม่ต้องตรวจข้อมูลเองซ้ำ ๆ อีก และ BaseMethod ซ่อนเงื่อนไขบังคับของ meta (ต้องมี key, category, name) ไว้ในตัว:

class BaseMethod { constructor(meta) { if (!meta || !meta.key || !meta.category || !meta.name) { throw new Error('method meta ต้องมี key, category และ name'); } this.meta = meta; } }

2.4.3 Composition (การประกอบวัตถุ)

registry.js ประกอบวัตถุวิธีคำนวณทั้ง 11 วัตถุเข้าเป็นระบบเดียว สังเกตว่าวิธีอนุพันธ์ทั้งสามตัว (Forward / Backward / Central) มาจากคลาสเดียวกันคือ DifferenceMethod แต่ถูกสร้างเป็น 3 วัตถุด้วยค่า kind ต่างกัน:

[ new BisectionMethod(), new NewtonRaphsonMethod(), new GaussEliminationMethod(), new LinearInterpolationMethod(), new LagrangeInterpolationMethod(), new LinearExtrapolationMethod(), new TrapezoidalRuleMethod(), new SimpsonsOneThirdRuleMethod(), new DifferenceMethod('forward'), new DifferenceMethod('backward'), new DifferenceMethod('central'), ].forEach(register);

แต่ละคลาสวิธีคำนวณยัง "ประกอบ" วัตถุอื่นเข้ามาใช้ เช่น ทุกคลาสประกอบวัตถุฟังก์ชัน f(x) ที่ได้จาก expression parser มาใช้คำนวณโดยไม่สนใจว่า parser เขียนอย่างไรภายใน

2.4.4 Polymorphism (พฤติกรรมหลากหลายรูปแบบ)

REST API ปลายทางเดียว POST /api/calculate ใช้คำนวณได้ทั้ง 11 วิธี — โค้ดเรียก method.solve(input) เพียงบรรทัดเดียว แต่พฤติกรรมจริงขึ้นอยู่กับว่า method เป็นวัตถุของคลาสใด (Bisection ก็แบ่งครึ่งช่วง, Gauss ก็ตัดตัวแปร):

// routes/index.js — โค้ดชุดเดียว ใช้กับวิธีใดก็ได้ (Polymorphism) const method = getMethod(methodKey); if (!method) { return res.status(400).json({ error: `ไม่พบวิธีคำนวณ '${methodKey}'` }); } const parsed = {}; // ... ตรวจอินพุตตาม field.type ของวิธีนั้น ... const result = method.solve(parsed); // ← คลาสไหนก็เรียกเหมือนกัน

2.4.5 Abstraction และ Inheritance

BaseMethod เป็นคลาสนามธรรม: ประกาศเมธอด solve() ไว้ให้คลาสลูกสืบทอดและเขียนทับ (override) ตามสูตรของตัวเอง ใครลืม implement โปรแกรมจะโยน error ทันที:

// BaseMethod.js — เมธอดนามธรรม /** @abstract */ solve(_input) { throw new Error(`วิธี '${this.meta.key}' ยังไม่ได้ implement เมธอด solve()`); } // roots.js — คลาสลูกเขียนทับด้วยอัลกอริทึมของตัวเอง class NewtonRaphsonMethod extends BaseMethod { solve({ fx, x0, tol, maxIter }) { // xᵢ₊₁ = xᵢ − f(xᵢ) / f'(xᵢ) ... } }

คลาสลูกทุกตัวได้คุณสมบัติร่วมจากคลาสแม่โดยอัตโนมัติ: โครงสร้าง meta แบบเดียวกัน, การถูกเก็บใน registry, และรูปแบบผลลัพธ์มาตรฐาน { answer, steps, table, meta } ที่ ResultView นำไปแสดงผลได้ทุกวิธีโดยไม่ต้องมีเงื่อนไขแยกวิธี

2.5 อัลกอริทึมที่สำคัญ

2.5.1 Expression Parser (ไม่ใช้ eval)

เพื่อความปลอดภัย โปรแกรมแยกวิเคราะห์สมการ f(x) จากสตริงด้วย Tokenizer + Recursive Descent Parser ที่เขียนขึ้นเอง รองรับตัวดำเนินการ + − * / ^ วงเล็บ ฟังก์ชัน sin cos tan sqrt exp ln log abs ค่าคงที่ pi, e และการคูณละเครื่องหมาย (2x, 3(x+1)):

function tokenize(src) { const tokens = []; let i = 0; while (i < src.length) { const ch = src[i]; if (/[0-9.]/.test(ch)) { // ตัวเลข (รวมเลขยกกำลัง 1e-6) const m = /^(?:\d+\.?\d*|\.\d+)(?:[eE][+-]?\d+)?/.exec(src.slice(i)); tokens.push({ type: 'num', value: parseFloat(m[0]) }); i += m[0].length; } else if (/[a-zA-Z_]/.test(ch)) { // ตัวแปร / ฟังก์ชัน / ค่าคงที่ ... } else if ('+-*/^(),'.includes(ch)) { tokens.push({ type: ch }); i++; } else { throw new ExprError(`ไม่รู้จักอักขระ '${ch}' ที่ตำแหน่งที่ ${i+1}`); } } return tokens; }

2.5.2 Bisection Method — การทำซ้ำแบบแบ่งครึ่งช่วง

solve({ fx, xl, xu, tol, maxIter }) { if (xl >= xu) throw ...; const fxl = evalAt(fx, xl, 'f(XL)'); const fxu = evalAt(fx, xu, 'f(XU)'); if (fxl * fxu > 0) { throw ...; // f(XL), f(XU) เครื่องหมายเดียวกัน → ใช้ Bisection ไม่ได้ } let a = xl, b = xu, prev = null, root; for (let iter = 0; iter < maxIter; iter++) { root = (a + b) / 2; // จุดกึ่งกลาง const froot = evalAt(fx, root, 'f(x)'); if (fa * froot < 0) b = root; else a = root; // เลือกครึ่งที่มีราก if (prev !== null && Math.abs((root - prev) / root) * 100 < tol) break; prev = root; } }

ทุกรอบการทำซ้ำถูกเก็บลงตาราง (XL, XU, XR, f(XL), f(XR), Error %) เพื่อแสดงให้ผู้ใช้เห็นการลู่เข้าของคำตอบทีละรอบ

2.5.3 Gauss Elimination — การตัดตัวแปรแบบ Partial Pivoting

for (let col = 0; col < n - 1; col++) { // เลือกแถวที่มีค่าสัมบูรณ์มากที่สุดในคอลัมน์นี้เป็น pivot (ลดปัญหาตัวเลข) let maxRow = col; for (let r = col + 1; r < n; r++) { if (Math.abs(A[r][col]) > Math.abs(A[maxRow][col])) maxRow = r; } [A[col], A[maxRow]] = [A[maxRow], A[col]]; [b[col], b[maxRow]] = [b[maxRow], b[col]]; if (Math.abs(A[col][col]) < 1e-12) { throw ...; // เมทริกซ์เอกฐน (singular) — แก้ระบบไม่ได้ } for (let r = col + 1; r < n; r++) { // ตัดตัวแปรแถวล่าง const m = A[r][col] / A[col][col]; for (let c = col; c < n; c++) A[r][c] -= m * A[col][c]; b[r] -= m * b[col]; } } // แทนค่าย้อนกลับ (Back Substitution)

3.1 ปัญหาที่พบระหว่างการพัฒนา

ปัญหาแนวทางแก้ไข
การใช้ eval() กับสมการ f(x) เสี่ยงต่อความปลอดภัยและข้อความ error อ่านไม่เข้าใจเขียน Expression Parser เอง (Tokenizer + Recursive Descent) แปลง error เป็นข้อความไทยระบุตำแหน่งอักขระที่ผิด เช่น "ไม่รู้จักอักขระ '@' ที่ตำแหน่งที่ 3"
การกรอกเมทริกซ์ฝั่งผู้ใช้ส่งชื่อ key ไม่ตรงกับฝั่งเซิร์ฟเวอร์ (A พิมพ์ใหญ่/เล็ก) ทำให้ได้ข้อความ "รูปแบบข้อมูลเมทริกซ์ไม่ถูกต้อง"ปรับ asMatrix ให้รับทั้ง key "a" และ "A" พร้อมเขียนชุดทดสอบ API ครอบคลุมกรณีนี้
หน้าเว็บขึ้น "Cannot read properties of null (reading 'categories')" เมื่อ API ยังไม่ตอบตั้ง Vite dev proxy ให้ /api ไปยังเซิร์ฟเวอร์ Express และเพิ่มการตรวจสอบ response ก่อน setState (Array.isArray(d.categories))
วิธี Simpson ต้องการจำนวนช่วงเป็นเลขคู่ แต่ผู้ใช้กรอกเลขคี่ได้ตรวจที่ด่าน validation แล้วแจ้งข้อความไทยพร้อมคำแนะนำให้กรอกใหม่
Newton-Raphson ไม่ลู่เข้าเมื่อ f'(x) = 0 หรือเริ่มที่จุดที่ไม่เหมาะสมไม่แอบอ้างว่าคำตอบถูก — แสดงค่าประมาณพร้อมแถบเตือนสีเหลืองอธิบายสาเหตุและแนะนำให้เปลี่ยน X0
โจทย์เดิมถูกบันทึกซ้ำ ๆ ทำให้ตารางประวัติรกใช้ SHA-256 hash ของ (หมวด + วิธี + อินพุตที่เรียง key แล้ว) เป็น UNIQUE constraint โจทย์เดิมจะเพิ่มแค่ "จำนวนครั้งที่คำนวณ"
